
In Windows environments, when a machine tries to resolve a hostname on the network and the DNS server has no answer, the operating system falls back to alternative name resolution protocols such as **LLMNR** (Link-Local Multicast Name Resolution) and **NBT-NS** (NetBIOS Name Service).

These protocols were designed to facilitate communication in small networks without full DNS infrastructure. However, their **broadcast-based** nature makes them inherently insecure: any device on the same network segment can respond to these queries, whether legitimate or not.

An attacker positioned on the same local network can exploit this to impersonate the host the victim is looking for, capturing the credentials that Windows automatically sends during the authentication process.

This type of attack is especially dangerous because:

- It requires no direct interaction with the victim
- Windows performs it automatically and silently
- It is enabled by default on all modern versions of Windows
- Captured credentials can be cracked offline or used in relay attacks


### LLMNR and NBT-NS

**Link-Local Multicast Name Resolution `(LLMNR)`** and **NetBIOS Name Service `(NBT-NS)`** are Microsoft Windows components that serve as fallback name resolution methods when DNS fails. When a host cannot be found via DNS, Windows automatically broadcasts a query to all devices on the local network segment asking if anyone knows the requested hostname.

The `LLMNR` protocol uses port `5355` over UDP natively. If LLMNR fails, `NBT-NS` is used instead, which is responsible for identifying systems on the local network by their NetBIOS name. This protocol uses port `137` over UDP.

 
### Why are they vulnerable by default in Windows? 

By default, these protocols broadcast queries to all hosts on the network segment. This means that any device on the same network can respond to these requests, whether legitimate or not. An attacker can abuse this behavior by poisoning LLMNR and NBT-NS queries using a tool like Responder, impersonating a host that is supposed to belong to the network domain and capturing the authentication traffic that Windows sends automatically.


**Example the poisoning for LLMNR\NBT-NS**

<img src="/budahacksecurity/uploads/md_images/llmnr-nbt-ns/llmnr.png" style="max-width:100%; border-radius:8px;">



The complete attack flow step by step:

1. The victim attempts to access `\\fileserver`
2. DNS cannot find the host and responds with `NXDOMAIN`
3. Windows broadcasts an `LLMNR/NBT-NS` query to the entire network
4. Responder intercepts the broadcast and replies impersonating `\\fileserver`
5. The victim automatically authenticates by sending its `NTLMv2` hash
6. Responder captures and saves the hash for offline cracking

### **Real-world Impact**

The impact of this technique is quite severe. Even in 2026, LLMNR and NBT-NS poisoning remains a fully functional attack vector that continues to affect organizations worldwide. Despite being a well-known vulnerability, most Windows environments still have these protocols enabled by default, making this technique relevant in modern penetration testing and real-world attacks.

The consequences of a successful attack can include:

- Capture of valid `NTLMv2` credentials from domain users
- Lateral movement across the network using captured hashes
- Full domain compromise if a privileged user account is captured
- Pass-the-Hash or NTLM Relay attacks without even needing to crack the hash

The fact that this attack requires **no prior access**, **no exploitation**, and **no interaction from the victim** beyond normal network activity makes it one of the most dangerous passive techniques in an internal network assessment.

### Attack from Linux using Responder

On Linux systems, the tool of choice for LLMNR and NBT-NS poisoning is **Responder**, developed by Laurent Gaffié. It listens on the network interface and automatically responds to broadcast queries, capturing `NTLMv2` hashes from Windows targets.

We can also verify if LLMNR and NBT-NS are active on the target using **Responder** in analyze mode. This method is completely passive — it listens for broadcast queries without sending any poisoned responses.


```
sudo python3 Responder.py -I vboxnet0 -A
```

<img src="/budahacksecurity/uploads/md_images/llmnr-nbt-ns/llmnr3.png" style="max-width:100%; border-radius:8px;">

Responder running in analyze mode (`-A` flag), confirming that the target `192.168.56.101` is actively broadcasting LLMNR, NBT-NS and MDNS queries for the non-existent host `fileserver`. No poisoned responses were sent at this stage.


**Responder Poising**

```
sudo python3 Responder.py -I vboxnet0 -wF
```

<img src="/budahacksecurity/uploads/md_images/llmnr-nbt-ns/llmnr4.png" style="max-width:100%; border-radius:8px;">


Responder successfully poisoned LLMNR, NBT-NS and MDNS queries from the target `192.168.56.101`, capturing the `NTLMv2` hash of the user `prueba` on machine `DESKTOP-PU9T0VF`


### cracking Hash NTLMV2  hashcat and Jhon The Ripper

After capturing the NTLMv2 hash, we located the file stored by Responder in the logs directory and proceeded to crack it offline using Hashcat and John The Ripper with the `rockyou.txt` wordlist.

### Attack from Windows using Inveigh


If we have access to the target Windows machine with administrator privileges, we can perform the same LLMNR and NBT-NS poisoning attack directly from Windows using **Inveigh**, a PowerShell-based tool that replicates the functionality of Responder.

Import Module Inveigh and start poising attack:

```
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
Import-Module .\Inveigh.ps1
Invoke-Inveigh -ConsoleOutput Y -LLMNR Y -NBNS Y -FileOutput Y
```

<img src="/budahacksecurity/uploads/md_images/llmnr-nbt-ns/llmnr7.png" style="max-width:100%; border-radius:8px;">


Inveigh successfully captured the NTLMv2 hash of user `prueba` from the victim machine `192.168.56.101 (DESKTOP-PU9T0VF)` via SMB port 445. The hash was automatically saved to `Inveigh-NTLMv2.txt` for offline cracking.


### Inveight.exe

`Inveigh.exe` is the original C# version of Inveigh, offering improved performance and additional features compared to the PowerShell module. It performs the same LLMNR and NBT-NS poisoning attack but runs as a standalone executable, making it ideal for scenarios where PowerShell execution is restricted.

```
.\Inveigh.exe
```
